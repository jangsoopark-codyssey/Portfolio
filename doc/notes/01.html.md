# HTML 기본 구조 및 브라우저 렌더링

## 1. `<html>`, `<head>`, `<body>`의 역할

### 질문

- `<html>` 태그는 이 문서가 HTML로 구성된다는 것을 알리는 태그로 보이며, 그 아래에는 `<head>`, `<body>` 태그가 존재한다.
- `<head>`와 `<body>`는 각각 어떠한 역할을 수행하는가?

### 답변

HTML 문서의 기본적인 구조는 다음과 같다.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    ...
</head>

<body>
    ...
</body>
</html>
```

엄밀하게 구분하면 `<html>`은 해당 문서가 HTML이라는 것을 선언하는 태그라기보다 **HTML 문서의 최상위 요소(Root Element)**이다.

HTML5 문서임을 브라우저에 알리는 역할은 다음의 선언이 담당한다.

```html
<!DOCTYPE html>
```

따라서 기본적인 문서 구조는 다음과 같이 표현할 수 있다.

```text
Document
│
├── <!DOCTYPE html>
│
└── <html>
     │
     ├── <head>
     │
     └── <body>
```

### `<head>`

`<head>`는 **문서 자체에 대한 정보와 설정(Metadata)**을 포함한다.

예를 들어 다음과 같은 요소가 포함된다.

```html
<head>
    <meta charset="UTF-8">

    <meta
        name="viewport"
        content="width=device-width, initial-scale=1.0"
    >

    <meta
        name="description"
        content="Portfolio of Jangsoo Park..."
    >

    <title>Jangsoo Park | Portfolio</title>

    <link rel="icon" href="./favicon.ico">

    <link rel="stylesheet" href="./css/variables.css">
    <link rel="stylesheet" href="./css/style.css">
</head>
```

주요 역할은 다음과 같다.

- 문자 인코딩 설정
- Viewport 설정
- 문서 제목 설정
- 검색 엔진 등에 제공할 Metadata 정의
- Favicon 설정
- CSS와 같은 외부 리소스 연결
- 브라우저가 문서를 처리하기 위해 필요한 각종 정보 제공

즉, `<head>`에는 **페이지의 내용 자체보다는 페이지를 해석하고 표현하기 위한 정보**가 위치한다.

### `<body>`

`<body>`는 **사용자에게 제공되는 문서의 본문 콘텐츠**를 포함한다.

```html
<body>
    <header>...</header>

    <main>
        <section>...</section>
        <section>...</section>
    </main>

    <footer>...</footer>
</body>
```

Portfolio를 기준으로 Hero, About, Skills, Projects, Contact 등의 실제 콘텐츠가 `<body>` 내부에 위치한다.

전체적인 역할을 구분하면 다음과 같다.

```text
HTML Document
│
├── head
│   └── 문서에 대한 정보 및 설정
│
└── body
    └── 실제 문서 콘텐츠
```

## 2. `<header>`, `<main>`, `<footer>`, `<div>`, `<section>`, `<nav>`, `<aside>`의 차이

### 질문

다음 요소들은 각각 어떠한 차이가 있는가?

- `<header>`
- `<main>`
- `<footer>`
- `<div>`
- `<section>`
- `<nav>`
- `<aside>`

이들 대부분을 `<div>` 요소로 구현하는 것도 가능한 것으로 보인다. 각각 별도의 요소를 사용하는 역할과 목적은 무엇인가?

### 답변

기술적으로 대부분의 영역을 `<div>` 요소로 구현할 수 있다.

예를 들어 다음과 같이 구성할 수 있다.

```html
<body>
    <div>메뉴</div>

    <div>
        <div>Hero</div>
        <div>About</div>
        <div>Skills</div>
    </div>

    <div>Copyright</div>
</body>
```

CSS를 적절하게 적용하면 `<header>`, `<main>`, `<section>`, `<footer>` 등을 사용한 페이지와 시각적으로 동일한 결과를 만들 수 있다.

그러나 `<div>`는 해당 영역이 **무엇을 의미하는지 표현하지 않는다.**

이를 보완하기 위하여 HTML에서는 **Semantic HTML** 요소를 제공한다.

Semantic HTML은 문서의 각 영역이 어떠한 의미와 역할을 가지는지 HTML 구조 자체에 표현하는 방식이다.

### `<div>`

`division`을 의미하며 특별한 의미를 가지지 않는 **범용 컨테이너**이다.

```html
<div class="project-card">
    ...
</div>
```

주로 다음과 같은 목적으로 사용한다.

- 여러 요소를 하나의 그룹으로 구성
- CSS 적용을 위한 컨테이너 생성
- JavaScript에서 하나의 영역으로 제어

즉, 별도의 의미가 필요하지 않은 단순한 묶음에 적합하다.

### `<header>`

문서 또는 특정 영역의 **머리말 또는 도입부**를 나타낸다.

```html
<header>
    <a>Jangsoo Park</a>

    <nav>
        ...
    </nav>
</header>
```

일반적으로 다음과 같은 내용이 포함될 수 있다.

- 로고
- 제목
- 소개
- Navigation

`<header>`는 반드시 웹 페이지의 가장 위에 한 번만 존재해야 하는 요소는 아니다.

예를 들어 다음과 같이 `<article>` 내부에서도 사용할 수 있다.

```html
<article>
    <header>
        <h2>HTML이란?</h2>
        <p>작성자: Jangsoo Park</p>
    </header>

    ...
</article>
```

따라서 `<header>`는 **해당 문서 또는 콘텐츠 영역의 도입부**를 의미한다.

### `<main>`

현재 문서의 **핵심 콘텐츠**를 나타낸다.

Portfolio에서는 다음과 같은 구조가 이에 해당한다.

```html
<main>
    <section id="hero">...</section>
    <section id="about">...</section>
    <section id="skills">...</section>
    <section id="projects">...</section>
    <section id="contact">...</section>
</main>
```

Hero, About, Skills, Projects, Contact는 Portfolio 페이지가 전달하려는 핵심 내용이므로 `<main>` 내부에 위치한다.

### `<footer>`

문서 또는 특정 콘텐츠의 **마무리 영역**을 나타낸다.

```html
<footer>
    <p>© 2026 Jangsoo Park</p>
</footer>
```

일반적으로 다음과 같은 정보가 포함될 수 있다.

- Copyright
- 연락처
- 관련 링크
- 작성자 정보
- 법적 정보

`<header>`와 마찬가지로 페이지 전체뿐만 아니라 특정 콘텐츠 영역 내부에서도 사용할 수 있다.

### `<nav>`

`Navigation`을 의미하며 **주요 탐색 링크를 제공하는 영역**을 나타낸다.

```html
<nav id="navigation">
    <ul>
        <li><a href="#hero">Home</a></li>
        <li><a href="#about">About</a></li>
        <li><a href="#skills">Skills</a></li>
        <li><a href="#projects">Projects</a></li>
    </ul>
</nav>
```

이를 `<div>`로 구현하는 것도 가능하다.

```html
<div id="navigation">
    ...
</div>
```

그러나 `<nav>`를 사용하면 해당 영역이 단순한 컨테이너가 아니라 **사용자가 페이지 또는 사이트를 탐색하기 위한 영역**이라는 의미가 HTML 구조에 포함된다.

### `<section>`

문서 내부에서 **하나의 주제를 이루는 구역**을 나타낸다.

Portfolio에서는 다음과 같이 사용할 수 있다.

```html
<main>
    <section id="hero">
        ...
    </section>

    <section id="about">
        ...
    </section>

    <section id="skills">
        ...
    </section>

    <section id="projects">
        ...
    </section>
</main>
```

각 `<section>`은 다음과 같이 서로 다른 주제를 담당한다.

```text
Hero
About
Skills
Projects
Contact
```

따라서 다음과 같이 구분할 수 있다.

```text
<div>
특별한 의미가 없는 일반적인 묶음

<section>
하나의 주제 또는 의미를 가지는 문서 구역
```

### `<aside>`

현재 주요 콘텐츠와 관련되어 있지만 **주요 콘텐츠의 흐름에서는 부가적인 내용**을 나타낸다.

예를 들어 블로그 페이지에서는 다음과 같이 사용할 수 있다.

```html
<main>
    <article>
        HTML에 대한 글...
    </article>

    <aside>
        관련 글
        저자 소개
        기타 부가 정보
    </aside>
</main>
```

Portfolio의 현재 구조에서는 반드시 필요한 요소는 아니다.

### 정리

| 요소 | 의미 |
|---|---|
| `<div>` | 특별한 의미가 없는 범용 컨테이너 |
| `<header>` | 문서 또는 영역의 머리말 및 도입부 |
| `<main>` | 문서의 핵심 콘텐츠 |
| `<footer>` | 문서 또는 영역의 마무리 |
| `<nav>` | 주요 탐색 링크 영역 |
| `<section>` | 특정 주제를 가지는 문서 구역 |
| `<aside>` | 주요 콘텐츠와 관련된 부가 콘텐츠 |

핵심적인 차이는 **시각적 표현이 아니라 의미(Semantics)**에 있다.

다음 두 요소는 동일한 CSS를 적용하면 동일하게 표현할 수 있다.

```html
<div id="navigation">
```

```html
<nav id="navigation">
```

그러나 두 번째 방법은 해당 영역이 Navigation이라는 의미를 HTML 문서 자체에 포함한다.

## 3. HTML에서 CSS와 JavaScript 파일을 사용하는 용어

### 질문

HTML에서 CSS, JavaScript 등의 외부 파일을 불러오는 것을 어떠한 용어로 표현하는가?

### 답변

일반적으로 **외부 리소스(External Resource)를 로드(Load)한다**고 표현할 수 있다.

CSS의 경우 다음과 같다.

```html
<link rel="stylesheet" href="./css/style.css">
```

다음과 같이 표현할 수 있다.

> 외부 Stylesheet를 연결(Link)한다.  
> 외부 CSS 리소스를 로드(Load)한다.

JavaScript의 경우 다음과 같다.

```html
<script src="./js/main.js"></script>
```

다음과 같이 표현할 수 있다.

> 외부 JavaScript 파일을 로드한다.

CSS와 JavaScript를 포괄하여 설명할 경우 **외부 리소스를 로드한다**는 표현이 적절하다.

`import`라는 표현을 사용할 때에는 주의가 필요하다.

JavaScript에는 실제로 다음과 같은 ES Module 문법이 존재하기 때문이다.

```javascript
import something from "./module.js";
```

따라서 `<link>` 또는 `<script>`를 통한 외부 파일 사용과 JavaScript의 `import`는 구분하는 것이 적절하다.

## 4. CSS와 JavaScript의 로드 위치

### 질문

CSS는 `<head>`에서 로드하고 JavaScript는 `<body>`의 마지막 부분에서 로드하는 형태를 확인할 수 있다.

- CSS와 JavaScript를 로드하는 위치가 정해져 있는가?
- 다른 위치에서 로드할 수 있는가?
- 위치에 따라 어떠한 차이가 발생하는가?

### 답변

CSS와 JavaScript의 위치가 모두 하나의 형태로 강제되는 것은 아니다.

다만 브라우저의 **HTML Parsing 및 Rendering 과정**과 관련하여 일반적으로 사용하는 위치가 존재한다.

### CSS

CSS는 일반적으로 `<head>`에서 로드한다.

```html
<head>
    <link rel="stylesheet" href="style.css">
</head>
```

브라우저가 HTML을 처리하는 초기 단계에서 CSS를 발견해야 페이지를 어떻게 표현할지 빠르게 결정할 수 있기 때문이다.

CSS를 늦게 발견할 경우 개념적으로 다음과 같은 현상이 발생할 수 있다.

```text
스타일이 적용되지 않은 콘텐츠
        │
        ▼
CSS 발견 및 로드
        │
        ▼
스타일 적용
        │
        ▼
화면의 시각적 변화
```

따라서 Stylesheet는 일반적으로 `<head>`에 배치하여 브라우저가 가능한 한 일찍 발견하도록 한다.

### JavaScript

전통적으로 JavaScript는 다음과 같이 `<body>` 마지막 부분에 배치하는 방법이 많이 사용되었다.

```html
<body>
    ...

    <script src="./js/main.js"></script>
</body>
```

일반적인 `<script>`를 만났을 때 HTML Parser의 진행에 영향을 줄 수 있기 때문이다.

단순화하면 다음과 같다.

```text
HTML Parsing
     │
     ▼
<script> 발견
     │
     ▼
JavaScript 로드 및 실행
     │
     ▼
HTML Parsing 계속
```

또 다른 이유는 JavaScript가 HTML 요소를 조작할 수 있기 때문이다.

예를 들어 다음 JavaScript가 존재한다고 가정한다.

```javascript
const button = document.querySelector("#menu-button");
```

HTML이 다음 순서로 작성되어 있다면,

```html
<script src="main.js"></script>

<button id="menu-button">
    Menu
</button>
```

JavaScript가 실행되는 시점에는 `<button>` 요소가 아직 HTML Parser에 의해 처리되지 않았을 가능성이 있다.

반대로 다음과 같이 작성하면,

```html
<button id="menu-button">
    Menu
</button>

<script src="main.js"></script>
```

JavaScript가 실행되는 시점에는 `<button>` 요소가 이미 DOM에 생성되어 있다.

따라서 전통적으로 JavaScript를 `<body>`의 마지막 부분에 배치하는 방법이 많이 사용되었다.

### `<head>`에서 JavaScript 로드

JavaScript를 반드시 `<body>` 마지막에서 로드해야 하는 것은 아니다.

다음과 같이 `<head>`에서 로드할 수도 있다.

```html
<head>
    <script src="./js/main.js" defer></script>
</head>
```

`defer`를 사용하면 HTML Parsing을 진행하면서 JavaScript 파일을 다운로드하고, HTML Parsing이 완료된 이후 JavaScript를 실행할 수 있다.

개념적으로 다음과 같다.

```text
시간 ──────────────────────────────▶

HTML Parsing
██████████████████████████████████

JS Download
      ███████████████████

JS Execution
                                  ███
```

따라서 기본적인 구분은 다음과 같다.

```text
CSS
└── 일반적으로 <head>에서 로드

JavaScript
├── <body> 마지막에서 로드
└── <head>에서 defer와 함께 로드
```

`async`, `defer`, `type="module"`을 사용하면 다운로드와 실행 시점이 달라지며, 이는 JavaScript의 실행 방식과 함께 별도로 구분하여 이해할 필요가 있다.

## 5. HTML Parsing과 DOM Tree

### 질문

HTML 문서를 Rendering하기 위해서는 Tree를 만드는 것으로 알고 있다.

해당 Tree는 어떠한 형태로 구성되는가?

### 답변

브라우저는 HTML 문서를 Parsing하여 **DOM(Document Object Model) Tree**를 생성한다.

다음 HTML을 예로 들 수 있다.

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <title>Portfolio</title>
</head>

<body>
    <header>
        <nav>
            <a href="#about">About</a>
        </nav>
    </header>

    <main>
        <section id="about">
            <h1>About Me</h1>
            <p>Hello!</p>
        </section>
    </main>

    <footer>
        <p>Copyright</p>
    </footer>
</body>

</html>
```

HTML Parser가 위 문서를 처리하면 개념적으로 다음과 같은 DOM Tree가 구성된다.

```text
Document
│
└── html
    │
    ├── head
    │   │
    │   └── title
    │       │
    │       └── "Portfolio"
    │
    └── body
        │
        ├── header
        │   │
        │   └── nav
        │       │
        │       └── a
        │           │
        │           └── "About"
        │
        ├── main
        │   │
        │   └── section#about
        │       │
        │       ├── h1
        │       │   └── "About Me"
        │       │
        │       └── p
        │           └── "Hello!"
        │
        └── footer
            │
            └── p
                │
                └── "Copyright"
```

HTML 코드와 DOM은 동일한 개념이 아니다.

HTML은 파일에 작성된 **문서 또는 문자열 형태의 원본 데이터**이며, DOM은 브라우저가 HTML을 Parsing하여 메모리상에 구성한 **객체 기반 Tree 구조**이다.

```text
index.html
HTML Source
    │
    ▼
HTML Parser
    │
    ▼
DOM
Object Tree
```

따라서 JavaScript의 다음 코드는

```javascript
document.querySelector("#about");
```

`index.html` 파일의 문자열을 직접 검색하는 것이 아니다.

브라우저가 HTML을 Parsing하여 생성한 **DOM에서 조건에 해당하는 Element를 검색하는 것**이다.

즉,

```text
HTML Source
    │
    │ Parsing
    ▼
DOM Tree
    │
    │ querySelector()
    ▼
Element 검색
```

이라는 관계로 이해할 수 있다.

## 6. DOM, CSSOM과 Rendering 과정

HTML뿐만 아니라 CSS도 브라우저에 의해 Parsing된다.

HTML은 DOM을 생성하고 CSS는 **CSSOM(CSS Object Model)**을 생성한다.

예를 들어 다음 CSS가 존재한다고 가정한다.

```css
body {
    margin: 0;
}

section {
    padding: 20px;
}

#about {
    background: white;
}
```

브라우저는 CSS를 Parsing하여 스타일 규칙을 표현하는 CSSOM을 구성한다.

전체적인 Rendering 과정은 다음과 같이 단순화할 수 있다.

```text
          HTML
            │
            ▼
       HTML Parser
            │
            ▼
        DOM Tree
            │
            │
            │
          CSS
            │
            ▼
       CSS Parser
            │
            ▼
       CSSOM Tree
            │
            │
            └────────────┐
                         │
DOM Tree ────────────────┤
                         │
                         ▼
                    Render Tree
                         │
                         ▼
                       Layout
                         │
                         ▼
                       Paint
                         │
                         ▼
                    화면에 출력
```

### DOM

DOM은 **문서의 구조와 콘텐츠**를 표현한다.

```text
body
├── header
├── main
│   ├── section#hero
│   ├── section#about
│   └── section#skills
└── footer
```

### CSSOM

CSSOM은 **각 요소에 적용될 수 있는 CSS 스타일 규칙**을 표현한다.

예를 들어 다음과 같은 정보가 포함된다.

```text
body
└── margin: 0

section
└── padding: 20px

#about
└── background: white
```

### Render Tree

브라우저는 DOM과 CSSOM의 정보를 이용하여 실제 화면을 그리는 데 필요한 **Render Tree**를 구성한다.

개념적으로 다음과 같은 관계를 가진다.

```text
DOM
문서의 구조
   │
   ├──────────┐
   │          │
   │        결합
   │          │
CSSOM         │
스타일 규칙   │
   │          │
   └──────────┘
        │
        ▼
   Render Tree
```

DOM에 존재한다고 해서 모든 요소가 반드시 Render Tree에 포함되는 것은 아니다.

예를 들어 다음과 같은 요소는 DOM에는 존재하지만 화면에는 표시되지 않는다.

```css
.hidden {
    display: none;
}
```

따라서 해당 요소는 일반적인 화면 Rendering을 위한 Render Tree에서 제외될 수 있다.

### Layout

Render Tree가 구성된 이후에는 각 요소가 화면에서 차지할 **크기와 위치를 계산**해야 한다.

예를 들어 다음과 같은 정보를 계산한다.

```text
Element A
x = 20px
y = 100px
width = 300px
height = 80px
```

이 과정을 **Layout**이라고 한다.

Layout은 Reflow라고 표현되는 경우도 있다.

### Paint

Layout을 통해 위치와 크기가 결정되면 실제로 화면에 표현할 시각적 정보를 그리는 과정이 필요하다.

예를 들어 다음과 같은 요소가 처리된다.

- 글자
- 배경
- 테두리
- 그림자
- 이미지

이 과정을 **Paint**라고 한다.

따라서 브라우저 Rendering 과정을 크게 단순화하면 다음과 같이 정리할 수 있다.

```text
HTML
 │
 ▼
DOM
 │
 ├──────────────┐
 │              │
CSS             │
 │              │
 ▼              │
CSSOM           │
 │              │
 └──────┬───────┘
        ▼
   Render Tree
        │
        ▼
      Layout
  위치 및 크기 계산
        │
        ▼
      Paint
  시각적 요소 그리기
        │
        ▼
      화면 출력
```

# 전체 구조 정리

HTML, CSS, JavaScript와 브라우저의 관계를 전체적으로 연결하면 다음과 같이 정리할 수 있다.

```text
                 Web Browser
                      │
        ┌─────────────┼─────────────┐
        │             │             │
        ▼             ▼             ▼
      HTML           CSS        JavaScript
        │             │             │
        ▼             ▼             │
 HTML Parser      CSS Parser         │
        │             │             │
        ▼             ▼             │
       DOM           CSSOM           │
        │             │             │
        └──────┬──────┘             │
               │                    │
               ▼                    │
          Render Tree               │
               │                    │
               ▼                    │
             Layout                 │
               │                    │
               ▼                    │
              Paint                 │
               │                    │
               ▼                    │
             화면 출력              │
                                    │
                                    ▼
                              DOM 접근 및 변경
                              CSS/Class 변경
                              Event 처리
```

핵심적인 관계는 다음과 같다.

```text
HTML
→ 문서의 구조와 콘텐츠 정의
→ Parsing
→ DOM 생성

CSS
→ 문서의 표현 방법 정의
→ Parsing
→ CSSOM 생성

DOM + CSSOM
→ Render Tree 구성
→ Layout
→ Paint
→ 화면 출력

JavaScript
→ DOM 접근 및 변경
→ 사용자 Event 처리
→ 페이지의 동적인 동작 구현
```

따라서 Portfolio의 `index.html`, CSS, JavaScript를 학습할 때에는 각각을 독립적인 파일로만 보는 것보다 다음 관계를 기준으로 이해하는 것이 적절하다.

**HTML은 문서의 구조를 정의하고, CSS는 해당 구조의 표현 방법을 정의하며, JavaScript는 생성된 DOM을 기반으로 문서의 상태와 동작을 제어한다.**
