# CSS 구조, 문법 및 스타일 관리

## 1. CSS 파일의 역할과 분리

### 질문

구현에서는 다음 두 개의 CSS 파일을 사용한다.

```text
css/
├── style.css
└── variables.css
```

각 파일의 역할은 무엇인가?

### 답변

CSS를 하나의 파일에 모두 작성할 수도 있지만, 현재 구현에서는 역할에 따라 두 파일로 분리하였다.

### `variables.css`

사이트 전체에서 반복적으로 사용하는 **공통 디자인 값(Design Tokens)**을 정의한다.

예를 들면 다음과 같다.

```css
:root {
    --color-background: #ffffff;
    --color-text: #222222;

    --font-size-small: 12px;
    --font-size-base: 16px;

    --spacing-small: 8px;
    --spacing-medium: 16px;
}
```

주로 다음과 같은 값이 포함된다.

- 색상
- Font Size
- 간격
- 크기
- 공통적으로 재사용되는 디자인 값

### `style.css`

실제 HTML 요소에 스타일과 Layout을 적용한다.

```css
body {
    color: var(--color-text);
    background: var(--color-background);
}

#header {
    position: fixed;
}

.project-card {
    padding: var(--spacing-medium);
}
```

두 파일의 역할은 다음과 같이 구분할 수 있다.

| 파일 | 역할 |
|---|---|
| `variables.css` | 공통으로 사용하는 디자인 값 정의 |
| `style.css` | 실제 HTML 요소의 스타일 및 Layout 정의 |

전체적인 관계는 다음과 같다.

```text
variables.css
    │
    ├── Color
    ├── Font Size
    ├── Spacing
    └── 기타 공통 값
          │
          ▼
      style.css
          │
          └── 실제 HTML 요소에 적용
```

# 2. `:root`

## 질문

`variables.css`에서 사용되는 `:root`는 무엇인가?

## 답변

`:root`는 문서 Tree의 **최상위 요소를 선택하는 Pseudo-class**이다.

HTML 문서에서는 사실상 `<html>` 요소를 선택한다.

```css
:root {
    --color-text: #222222;
}
```

다음 코드 역시 `<html>` 요소를 선택한다.

```css
html {
    color: black;
}
```

그러나 CSS Custom Property를 전역적으로 정의할 때에는 일반적으로 `:root`를 사용한다.

```css
:root {
    --color-primary: #000000;
    --font-size-base: 16px;
}
```

이렇게 정의한 값은 문서 전체에서 사용할 수 있다.

```css
p {
    color: var(--color-primary);
}
```

---

# 3. CSS Custom Property

다음과 같이 `--`로 시작하는 값은 **CSS Custom Property**이다.

```css
--color-primary: #000000;
--font-size-base: 16px;
```

일반적으로 CSS 변수라고도 표현한다.

예를 들어 다음과 같이 정의할 수 있다.

```css
:root {
    --color-primary: #222222;
}
```

그리고 다른 CSS 규칙에서 해당 값을 사용할 수 있다.

```css
body {
    color: var(--color-primary);
}
```

---

# 4. `var()`

## 질문

`style.css`에서 사용되는 `var()`는 무엇인가?

## 답변

`var()`는 **CSS Custom Property의 값을 참조하는 CSS 함수**이다.

다음과 같이 변수가 정의되어 있다고 가정한다.

```css
:root {
    --color-primary: #222222;
}
```

다른 CSS에서 다음과 같이 사용할 수 있다.

```css
body {
    color: var(--color-primary);
}
```

개념적으로 다음과 같은 관계이다.

```text
variables.css

--color-primary: #222222;
          │
          ▼
style.css

color: var(--color-primary);
```

브라우저는 최종적으로 해당 Custom Property의 값을 사용하여 스타일을 계산한다.

# 5. CSS의 기본 문법

CSS의 기본적인 구조는 다음과 같다.

```css
selector {
    property: value;
}
```

예를 들어 다음 CSS가 존재한다고 가정한다.

```css
.header {
    display: flex;
    height: 60px;
}
```

이를 구성 요소별로 분해하면 다음과 같다.

```text
.header
│
└── Selector

{
    display: flex;
    ───────  ────
    Property Value

    height: 60px;
    ──────  ────
    Property Value
}
│
└── Declaration Block
```

CSS는 기본적으로 다음의 의미를 가진다.

> Selector로 HTML 요소를 선택하고, 해당 요소에 Property와 Value로 구성된 스타일을 적용한다.

---

# 6. `{ }`와 `[ ]`

## `{ }` — Declaration Block

중괄호 내부에는 선택한 요소에 적용할 CSS 선언이 위치한다.

```css
.header {
    display: flex;
    height: 60px;
}
```

기본 구조는 다음과 같다.

```text
Selector {
    Property: Value;
    Property: Value;
}
```

---

## `[ ]` — Attribute Selector

대괄호는 HTML Attribute를 기준으로 요소를 선택하는 **Attribute Selector**에 사용된다.

다음 HTML을 예로 들 수 있다.

```html
<input type="text">
<input type="email">
<input type="checkbox">
```

다음 CSS는 `type="email"`인 요소만 선택한다.

```css
input[type="email"] {
    ...
}
```

다음과 같이 특정 Attribute의 존재 여부만 검사할 수도 있다.

```css
[hidden] {
    display: none;
}
```

이는 다음 요소를 선택할 수 있다.

```html
<div hidden>...</div>
```

따라서 다음과 같이 구분할 수 있다.

```text
{ }
└── CSS 선언을 작성하는 영역

[ ]
└── HTML Attribute를 기준으로 요소를 선택
```

# 7. CSS Selector

## 질문

다음과 같이 `{ }` 앞에 작성되는 표현은 무엇인가?

```css
*
html
body
header
#header
.header
```

## 답변

이들을 **CSS Selector(선택자)**라고 한다.

Selector는 CSS가 **어떤 HTML 요소에 스타일을 적용할 것인지 지정하는 문법**이다.

---

## Universal Selector

```css
* {
    box-sizing: border-box;
}
```

`*`는 모든 요소를 선택한다.

이를 **Universal Selector**라고 한다.

---

## Type Selector

```css
body {
    margin: 0;
}

header {
    ...
}

section {
    ...
}
```

HTML 태그 이름을 이용하여 요소를 선택한다.

이를 **Type Selector** 또는 **Element Selector**라고 한다.

---

## ID Selector

HTML이 다음과 같다고 가정한다.

```html
<header id="header">
```

CSS에서는 다음과 같이 선택한다.

```css
#header {
    ...
}
```

`#`은 `id`를 기준으로 요소를 선택하는 **ID Selector**이다.

```text
#header
   │
   └── id="header"
```

---

## Class Selector

HTML이 다음과 같다고 가정한다.

```html
<header class="header">
```

CSS에서는 다음과 같이 선택한다.

```css
.header {
    ...
}
```

`.`은 `class`를 기준으로 요소를 선택하는 **Class Selector**이다.

```text
.header
   │
   └── class="header"
```

하나의 HTML 요소는 여러 개의 Class를 가질 수 있다.

```html
<button class="button active large">
```

다음 Selector들이 모두 해당 요소를 선택할 수 있다.

```css
.button { }
.active { }
.large { }
```

### 기본 Selector 정리

| Selector | 의미 |
|---|---|
| `*` | 모든 요소 |
| `body` | `<body>` 요소 |
| `header` | `<header>` 요소 |
| `#header` | `id="header"`인 요소 |
| `.header` | `class="header"`인 요소 |
| `[hidden]` | `hidden` Attribute를 가진 요소 |
| `[type="email"]` | `type="email"`인 요소 |

---

# 8. CSS Naming과 `-`, `__`, `--`

## 질문

다음과 같은 Class 이름에서 `-`, `__`, `--`의 사용 목적에는 차이가 있는가?

```css
.theme-switch__icon--light
```

## 답변

해당 형태는 **BEM(Block Element Modifier)**이라는 CSS Naming Convention과 관련된 구조이다.

다음과 같이 분해할 수 있다.

```text
theme-switch__icon--light
──────────── ──── ─────
   Block     Element Modifier
```

---

## `-`

일반적으로 여러 단어를 하나의 이름으로 연결하는 데 사용한다.

```css
.theme-switch
.project-card
.menu-button
```

예를 들어 다음과 같다.

```text
theme + switch
      ↓
theme-switch
```

---

## `__`

BEM에서 **Block 내부의 Element**를 표현한다.

```css
.theme-switch__icon
```

이는 다음 관계를 표현한다.

```text
theme-switch
└── icon
```

HTML에서는 다음과 같이 사용할 수 있다.

```html
<button class="theme-switch">
    <span class="theme-switch__icon"></span>
</button>
```

---

## `--`

BEM에서 **Modifier**를 표현한다.

Modifier는 특정 요소의 상태 또는 변형을 의미한다.

```css
.theme-switch__icon--light
.theme-switch__icon--dark
```

이를 구조적으로 표현하면 다음과 같다.

```text
theme-switch
│
└── __icon
    │
    ├── --light
    └── --dark
```

따라서

```css
.theme-switch__icon--light
```

는 다음 의미를 이름에 표현한다.

```text
Block
theme-switch

Element
icon

Modifier
light
```

BEM은 CSS 자체에서 강제하는 문법이 아니다.

브라우저 입장에서 `theme-switch__icon--light`는 하나의 Class 이름일 뿐이다.

BEM은 개발자가 코드의 구조와 역할을 쉽게 파악하기 위하여 사용하는 **Naming Convention**이다.

# 9. Pseudo-element

## 질문

다음과 같은 `::` 문법은 무엇인가?

```css
.element::before
```

## 답변

`::before`는 **Pseudo-element(가상 요소)**이다.

실제 HTML 요소를 별도로 작성하지 않고 특정 요소의 일부를 스타일 대상으로 만들 수 있다.

예를 들어 다음과 같다.

```css
.title::before {
    content: "•";
}
```

HTML은 다음과 같다.

```html
<h2 class="title">Projects</h2>
```

개념적으로 다음과 같은 구조가 만들어진다.

```text
h2.title
│
├── ::before
│   └── "•"
│
└── "Projects"
```

대표적인 Pseudo-element는 다음과 같다.

```css
::before
::after
```

# 10. Pseudo-class

## 질문

다음과 같은 `:` 문법은 무엇인가?

```css
.form-field input:focus
```

## 답변

`:focus`는 **Pseudo-class(의사 클래스)**이다.

Pseudo-class는 요소의 특정 상태나 조건을 기준으로 요소를 선택한다.

```css
input:focus {
    border: 2px solid black;
}
```

이는 현재 Focus를 가지고 있는 `<input>` 요소에 스타일을 적용한다.

대표적인 Pseudo-class는 다음과 같다.

```css
:hover
:focus
:active
:checked
:disabled
:first-child
:last-child
```

Pseudo-class와 Pseudo-element는 다음과 같이 구분한다.

```text
:
└── Pseudo-class
    요소의 상태 또는 조건

    :hover
    :focus
    :checked


::
└── Pseudo-element
    요소의 특정 가상 부분

    ::before
    ::after
```

# 11. `.project-filter.active`

## 질문

다음 Selector는 무엇을 의미하는가?

```css
.project-filter.active
```

## 답변

`.project-filter`와 `.active` Class를 **동시에 가지고 있는 하나의 요소**를 선택한다.

예를 들어 다음 요소가 선택된다.

```html
<button class="project-filter active">
```

개념적으로 다음과 같다.

```text
.project-filter
       AND
.active
```

공백의 존재 여부가 중요하다.

다음 두 Selector는 의미가 다르다.

```css
.project-filter.active
```

```css
.project-filter .active
```

첫 번째는 하나의 요소가 두 Class를 모두 가지는 경우이다.

```html
<button class="project-filter active">
```

두 번째는 `.project-filter` 요소의 내부에 존재하는 `.active` 요소를 의미한다.

```html
<div class="project-filter">
    <button class="active">...</button>
</div>
```

따라서 다음과 같이 구분한다.

```text
.project-filter.active
└── 하나의 요소가 두 Class를 모두 가짐


.project-filter .active
└── project-filter의 자손 중
    active Class를 가진 요소
```

# 12. `@media`

## 질문

`@media`는 무엇인가?

## 답변

`@media`는 **Media Query를 작성하기 위한 CSS At-rule**이다.

Media Query를 이용하면 화면 크기 또는 사용 환경에 따라 다른 CSS를 적용할 수 있다.

예를 들어 Mobile 환경에서 다음 스타일을 기본값으로 사용할 수 있다.

```css
.project-grid {
    grid-template-columns: 1fr;
}
```

Tablet 이상의 환경에서는 다음과 같이 변경할 수 있다.

```css
@media (min-width: 768px) {
    .project-grid {
        grid-template-columns: repeat(2, 1fr);
    }
}
```

이는 Viewport의 너비가 최소 `768px` 이상인 경우 내부 CSS를 적용한다는 의미이다.

Desktop에서는 다음과 같이 구성할 수 있다.

```css
@media (min-width: 1024px) {
    .project-grid {
        grid-template-columns: repeat(3, 1fr);
    }
}
```

Mobile-First 관점에서 표현하면 다음과 같다.

```text
Mobile
< 768px
│
│ 1 Column
│
├──────────── 768px
│
│ Tablet
│ 2 Columns
│
├──────────── 1024px
│
│ Desktop
│ 3 Columns
│
▼
```

Media Query는 화면 너비 이외의 조건에도 사용할 수 있다.

```css
@media (prefers-color-scheme: dark) {
    ...
}

@media (orientation: landscape) {
    ...
}

@media print {
    ...
}
```

따라서 `@media`는 **환경 조건에 따라 CSS 규칙을 선택적으로 적용하는 기능**이라고 할 수 있다.

# 13. CSS는 프로그래밍 언어인가?

## 질문

CSS는 프로그래밍 언어가 아닌 것으로 알고 있다.

CSS에서 가능한 것과 불가능한 것은 무엇인가?

## 답변

CSS는 일반적으로 **Programming Language가 아니라 Style Sheet Language**로 분류한다.

HTML, CSS, JavaScript는 다음과 같이 구분할 수 있다.

```text
HTML
│
└── Markup Language
    문서의 구조와 의미 정의


CSS
│
└── Style Sheet Language
    문서의 표현 방법 정의


JavaScript
│
└── Programming Language
    로직과 동작 정의
```

---

## CSS에서 가능한 기능

### 변수

```css
:root {
    --header-height: 60px;
}

header {
    height: var(--header-height);
}
```

### 계산

```css
main {
    width: calc(100% - 40px);
}
```

### 조건부 스타일

```css
@media (min-width: 768px) {
    ...
}
```

### 요소의 상태에 따른 스타일

```css
button:hover {
    ...
}

input:focus {
    ...
}
```

### Transition

```css
button {
    transition: opacity 0.3s;
}
```

### Animation

```css
@keyframes fade-in {
    from {
        opacity: 0;
    }

    to {
        opacity: 1;
    }
}
```

### Layout

Flexbox:

```css
.container {
    display: flex;
}
```

Grid:

```css
.container {
    display: grid;
}
```

따라서 현대 CSS는 단순한 색상 지정 언어보다 훨씬 많은 표현 및 조건 처리 기능을 제공한다.

---

## CSS가 담당하지 않는 기능

CSS는 일반적인 Application Logic을 구현하기 위한 언어가 아니다.

다음과 같은 처리는 일반적으로 JavaScript의 역할이다.

```text
사용자 입력
    │
    ▼
데이터 저장
    │
    ▼
알고리즘 실행
    │
    ▼
HTTP 요청
    │
    ▼
JSON Parsing
    │
    ▼
DOM 생성 또는 변경
```

예를 들어 다음과 같은 처리는 JavaScript로 구현한다.

```javascript
const response = await fetch("/api/projects");
const projects = await response.json();

for (const project of projects) {
    createProjectCard(project);
}
```

CSS에는 일반적인 Programming Language의 의미에서 다음 기능이 존재하지 않는다.

```text
일반 목적 함수 정의 및 호출
명령형 반복문 실행
HTTP 요청
파일 I/O
DOM 요소 생성 및 삭제
임의의 Event Handler 실행
일반 목적 알고리즘 구현
```

다만 현대 CSS에는 변수, 계산, 조건적인 Selector, Media Query 등의 기능이 존재하므로 단순히 "CSS에는 로직이 존재하지 않는다"고 정의하는 것은 정확하지 않다.

핵심적인 차이는 각 언어가 담당하는 역할에 있다.

```text
HTML
"What is it?"
무엇이 존재하는가?
        │
        ▼
문서 구조


CSS
"How should it look?"
```

# 14. CSS 파일은 하나로 작성하는가, 여러 파일로 분리하는가?

## 질문

CSS를 이용하여 스타일을 작성할 때 파일을 여러 개로 나누어 관리할 수 있다는 것은 확인하였다.

실제 프로젝트에서는 CSS를 의미적으로 분할하는가, 아니면 하나의 `style.css`에 작성하는가?

파일을 분리하면 가독성과 유지보수성은 향상될 수 있지만 네트워크 요청 횟수가 증가할 수 있으므로 Trade-off가 존재하는 것으로 보인다.

## 답변

두 방식 모두 사용할 수 있으며 프로젝트의 규모와 개발 환경에 따라 결정한다.

작은 프로젝트에서는 다음과 같이 하나의 CSS 파일만 사용할 수도 있다.

```text
css/
└── style.css
```

프로젝트의 규모가 커지면 일반적으로 **역할이나 Component 등의 의미를 기준으로 분리**한다.

예를 들어 다음과 같이 구성할 수 있다.

```text
css/
├── variables.css
├── reset.css
├── layout.css
│
├── components/
│   ├── header.css
│   ├── button.css
│   ├── project-card.css
│   └── form.css
│
└── pages/
    └── home.css
```

대표적인 분리 기준은 다음과 같다.

| 분리 기준 | 예 |
|---|---|
| 역할 | `variables.css`, `reset.css`, `layout.css` |
| Component | `button.css`, `card.css`, `header.css` |
| Page | `home.css`, `about.css` |
| 기능 | `theme.css`, `animation.css` |

# 15. CSS 파일 분리와 Network Request

HTML에서 여러 CSS 파일을 각각 직접 로드하면 각각의 외부 리소스에 대한 요청이 발생할 수 있다.

```html
<link rel="stylesheet" href="variables.css">
<link rel="stylesheet" href="reset.css">
<link rel="stylesheet" href="layout.css">
<link rel="stylesheet" href="header.css">
<link rel="stylesheet" href="button.css">
```

개념적으로 다음과 같다.

```text
Browser
   │
   ├── GET variables.css
   ├── GET reset.css
   ├── GET layout.css
   ├── GET header.css
   └── GET button.css
```

따라서 하나의 CSS 파일과 여러 CSS 파일 사이에는 다음과 같은 Trade-off가 존재할 수 있다.

```text
하나의 CSS 파일
────────────────────────────

장점
├── 요청할 Resource 수 감소
└── 배포 구조가 단순함

단점
├── 파일 크기 증가
├── 코드 탐색 어려움
└── 유지보수성 저하 가능


여러 CSS 파일
────────────────────────────

장점
├── 의미적 분리
├── 유지보수 용이
├── 코드 탐색 용이
└── 협업 용이

단점
├── 요청할 Resource 수 증가 가능
└── CSS 간 의존성과 적용 순서 관리 필요
```

# 16. 개발 구조와 배포 구조의 분리

현대적인 웹 개발에서는 **개발 단계의 파일 구조와 실제 배포되는 파일 구조를 분리**할 수 있다.

개발 단계에서는 사람이 관리하기 편하도록 CSS를 여러 파일로 작성한다.

```text
src/
├── variables.css
├── reset.css
├── header.css
├── projects.css
└── contact.css
```

이후 Vite, Webpack 등의 Build Tool을 이용하여 배포 과정에서 CSS를 처리할 수 있다.

```text
개발 단계

variables.css ──┐
reset.css ──────┤
header.css ─────┤
projects.css ───┼────→ Build
contact.css ────┘
                         │
                         ▼

배포 단계

                  index-xxxxx.css
```

따라서 다음 두 문제를 반드시 동일하게 볼 필요는 없다.

```text
개발자가 CSS를 어떻게 관리할 것인가?
                │
                │
                ≠
                │
                ▼
브라우저에 CSS를 어떻게 전달할 것인가?
```

즉, 개발자는 유지보수성을 위해 CSS를 의미적으로 분리하면서도 Build 과정에서 실제 배포 형태를 최적화할 수 있다.

HTTP/2 및 HTTP/3 환경에서는 HTTP/1.x 환경보다 여러 Resource 요청에 따른 비용도 완화되었으므로 단순히 CSS 파일의 개수가 적을수록 항상 좋은 구조라고 판단할 수는 없다.

# 18. CSS 파일 분리의 핵심 관점

CSS 파일 분할의 주요 목적은 **의미적 분리와 유지보수성 확보**이다.

Network Request와 배포 성능은 별도의 최적화 문제로 다룰 수 있다.

```text
Source Code 관점
│
└── 사람이 관리하기 좋은 구조
    ├── 의미적 분리
    ├── 가독성
    ├── 유지보수성
    └── 협업


Build / Deployment 관점
│
└── 브라우저가 효율적으로 받을 수 있는 구조
    ├── Bundle
    ├── Minification
    ├── Cache
    └── Network 최적화
```

따라서 CSS 파일 구조를 설계할 때에는 단순히 파일 수를 최소화하는 것보다 **각 파일의 책임이 명확한가**를 우선적으로 고려할 수 있다.

현재 Portfolio의 구조에서는 다음과 같이 이해할 수 있다.

```text
variables.css
    │
    │ 공통 디자인 값 제공
    ▼
style.css
    │
    │ HTML 요소에 실제 스타일 적용
    ▼
HTML
    │
    ▼
Browser Rendering
```

# 19. CSS 코드 해석의 기본 단위

`style.css`를 한 줄씩 분석할 때 가장 기본적인 단위는 다음과 같다.

```css
.project-filter.active {
    background-color: var(--color-primary);
}
```

이를 문법적으로 분해하면 다음과 같다.

```text
.project-filter.active
│
└── Selector
    │
    ├── .project-filter
    └── .active
         │
         └── 두 Class를 동시에 가진 요소 선택


{
    background-color
    │
    └── Property

    :

    var(--color-primary)
    │
    └── Value
        │
        └── CSS Custom Property 참조
}
```

따라서 CSS를 읽는 기본적인 순서는 다음과 같이 정리할 수 있다.

```text
1. Selector 확인
   │
   └── 어떤 HTML 요소를 선택하는가?

2. Property 확인
   │
   └── 해당 요소의 무엇을 변경하는가?

3. Value 확인
   │
   └── 어떠한 값으로 설정하는가?

4. 상태 및 조건 확인
   │
   ├── :hover
   ├── :focus
   ├── .active
   └── @media

5. Cascade 및 적용 순서 확인
   │
   └── 여러 CSS 규칙이 충돌할 경우
       어떤 규칙이 최종적으로 적용되는가?
```

이 구조를 기준으로 CSS 코드를 분석하면 `style.css`의 개별 규칙뿐만 아니라 전체 스타일 구조를 체계적으로 파악할 수 있다.
