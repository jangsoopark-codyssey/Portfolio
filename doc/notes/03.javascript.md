# JavaScript 기본 문법, 모듈 구조 및 브라우저 동작

## 1. JavaScript의 특징

### 질문

JavaScript는 전반적으로 일반적인 프로그래밍 언어와 유사한 것으로 보인다.

### 답변

JavaScript는 HTML, CSS와 달리 **Programming Language**이다.

HTML, CSS, JavaScript의 역할은 다음과 같이 구분할 수 있다.

```text
HTML
└── Markup Language
    문서의 구조와 의미 정의

CSS
└── Style Sheet Language
    문서의 표현 방법 정의

JavaScript
└── Programming Language
    로직과 동작 정의
```

JavaScript에서는 일반적인 프로그래밍 언어에서 사용하는 다음과 같은 기능을 제공한다.

- 변수
- 함수
- 조건문
- 반복문
- 객체
- 배열
- Class
- Module
- 비동기 처리
- 예외 처리

브라우저 환경에서는 JavaScript와 함께 DOM, Event, Network 등의 **Web API**를 사용할 수 있다.

# 2. Portfolio의 JavaScript 파일 구조

## 질문

현재 구현의 JavaScript 파일을 다음과 같이 이해할 수 있는가?

```text
main.js
└── 시작점

content.js
└── data/content.json을 로드하고 Rendering
    HTML은 큰 구조만 구성하므로
    세부 DOM 구조와 실제 Content 구성

github.js
└── GitHub API 요청 관련 구현

contact.js
└── Contact Form 관련 처리
```

## 답변

전반적인 이해는 적절하다.

각 파일은 서로 다른 책임을 가지도록 분리되어 있다.

### `main.js`

Application의 **Entry Point** 역할을 담당한다.

다른 Module의 기능을 가져오고 초기화하여 전체 동작을 시작한다.

개념적으로 다음과 같다.

```javascript
import { initContent } from "./content.js";
import { initContact } from "./contact.js";

initContent();
initContact();
```

```text
main.js
│
├── 필요한 Module Import
├── Content 초기화
├── Navigation 초기화
├── Event Listener 등록
└── 기타 Application 초기화
```

### `content.js`

`data/content.json`의 데이터를 이용하여 페이지의 실제 Content와 세부 DOM 구조를 구성한다.

예를 들어 `index.html`에 다음과 같은 큰 구조만 존재할 수 있다.

```html
<section id="skills">
    <ul id="skills-list"></ul>
</section>
```

JavaScript가 데이터를 이용하여 다음과 같은 세부 구조를 생성할 수 있다.

```html
<ul id="skills-list">
    <li>Python</li>
    <li>JavaScript</li>
    <li>PyTorch</li>
</ul>
```

따라서 다음과 같은 관계로 이해할 수 있다.

```text
index.html
│
└── 페이지의 기본 구조
          │
          ▼
content.js
│
├── content.json 로드
├── 데이터 해석
├── 세부 DOM 생성
└── Content 삽입
```

### `github.js`

GitHub API와 관련된 Network 통신을 담당한다.

```text
github.js
    │
    │ HTTP Request
    ▼
GitHub API
    │
    │ JSON Response
    ▼
github.js
    │
    └── 필요한 데이터 추출 및 가공
```

### `contact.js`

Contact Form과 관련된 사용자 입력과 Event를 처리한다.

```text
사용자 입력
    │
    ▼
Submit Event
    │
    ▼
입력값 확인
    │
    ▼
Validation
    │
    ▼
Form 처리
```

이처럼 파일마다 서로 다른 책임을 부여하는 것은 **Separation of Concerns**의 한 형태로 볼 수 있다.

# 3. `import ... from ...`

## 질문

다음 구문의 의미는 무엇인가?

```javascript
import ... from "...";
```

## 답변

다른 JavaScript Module이 `export`한 값을 현재 Module에서 가져오는 문법이다.

예를 들어 다음과 같다.

```javascript
import { loadContent } from "./content.js";
```

의존 관계는 다음과 같다.

```text
content.js
    │
    │ export
    ▼
loadContent
    │
    │ import
    ▼
main.js
```

`"./content.js"`의 `./`는 현재 파일의 위치를 기준으로 하는 **상대 경로(Relative Path)**를 의미한다.

# 4. `var`, `let`, `const`

## 질문

`var`, `let`, `const`의 차이는 무엇인가?

## 답변

세 문법 모두 변수를 선언하기 위해 사용하지만 Scope와 재할당 등의 특성에 차이가 있다.

### `var`

과거 JavaScript에서 주로 사용하던 변수 선언 방식이다.

```javascript
var count = 1;
count = 2;
```

Function Scope를 가지며 Hoisting 등의 특성이 존재한다.

현대 JavaScript에서는 일반적인 변수 선언에 `let`과 `const`를 주로 사용한다.

### `let`

값을 다시 할당해야 하는 변수에 사용한다.

```javascript
let count = 0;

count = count + 1;
```

### `const`

변수 자체에 다른 값을 다시 할당하지 않을 경우 사용한다.

```javascript
const name = "Jangsoo";
```

다음과 같은 재할당은 허용되지 않는다.

```javascript
const name = "Jangsoo";
name = "Park";
```

그러나 `const`가 객체 자체를 불변으로 만드는 것은 아니다.

```javascript
const user = {
    name: "Jangsoo"
};

user.name = "Park";
```

위 코드는 가능하다.

`const`는 `user`라는 변수가 다른 객체를 다시 가리키도록 재할당하는 것을 제한한다.

일반적인 사용 원칙은 다음과 같다.

```text
기본적으로 const 사용
        │
        ▼
재할당이 필요한 경우 let 사용
        │
        ▼
특별한 이유가 없다면 var 사용 지양
```

# 5. 비동기 프로그래밍과 `async`, `await`

## 질문

비동기 프로그래밍과 `async`, `await`는 무엇인가?

## 답변

웹에서는 즉시 완료되지 않는 작업이 많이 존재한다.

대표적인 예가 Network Request이다.

```text
JavaScript
    │
    ├── 서버에 Request
    │
    │      일정 시간 소요
    │
    └── Response
```

Network Response를 기다리는 동안 다른 작업까지 모두 정지시키는 것은 비효율적이다.

따라서 JavaScript에서는 이러한 작업을 비동기적으로 처리할 수 있다.

```javascript
async function loadContent() {
    const response = await fetch("./data/content.json");
    const data = await response.json();

    return data;
}
```

### `async`

함수를 비동기 함수로 선언한다.

```javascript
async function loadContent() {
    ...
}
```

`async` 함수는 항상 Promise를 반환한다.

### `await`

Promise의 처리가 완료될 때까지 해당 `async` 함수의 이후 실행을 논리적으로 대기시킨다.

```javascript
const response = await fetch("./data/content.json");
```

중요한 점은 `await`가 브라우저 전체의 실행을 정지시키는 것이 아니라는 것이다.

```text
fetch()
   │
   ├──────────────► Network 처리
   │
   │
   │ JavaScript는 다른 작업 처리 가능
   │
   ◄────────────── Response
   │
   ▼
await 이후 코드 실행 재개
```

이 과정은 JavaScript의 **Event Loop, Task Queue, Promise**와 연결된다.

# 6. `export`

## 질문

`export`는 무엇인가?

## 답변

현재 Module에 존재하는 함수, 변수, Class 등을 다른 Module에서 사용할 수 있도록 공개하는 문법이다.

```javascript
export function loadContent() {
    ...
}
```

다른 Module에서는 다음과 같이 가져올 수 있다.

```javascript
import { loadContent } from "./content.js";
```

관계를 정리하면 다음과 같다.

```text
export
현재 Module
    │
    └── 외부 Module에 기능 공개


import
외부 Module
    │
    └── 공개된 기능을 현재 Module로 가져옴
```

# 7. `replaceChildren()`

## 질문

`replaceChildren()`은 무엇인가?

## 답변

`replaceChildren()`은 DOM API가 제공하는 Method이다.

특정 DOM Element의 기존 자식 Node를 새로운 자식 Node로 교체한다.

다음 HTML을 예로 들 수 있다.

```html
<ul id="skills">
    <li>Old A</li>
    <li>Old B</li>
</ul>
```

다음 코드를 실행하면

```javascript
const skills = document.querySelector("#skills");

skills.replaceChildren();
```

모든 자식이 제거된다.

```html
<ul id="skills"></ul>
```

새로운 Element를 전달할 수도 있다.

```javascript
skills.replaceChildren(item1, item2);
```

개념적으로 다음과 같다.

```text
기존 상태

skills
├── Old A
└── Old B

        │
        │ replaceChildren(item1, item2)
        ▼

변경 상태

skills
├── item1
└── item2
```

# 8. `...` 문법

## 질문

함수 인자 등에 `...`으로 시작하는 문법은 무엇인가?

## 답변

`...`은 사용되는 위치에 따라 **Rest Syntax** 또는 **Spread Syntax**로 사용된다.

### Rest Parameter

함수의 Parameter 위치에서 사용하면 여러 Argument를 하나의 배열로 수집한다.

```javascript
function sum(...numbers) {
    ...
}
```

다음과 같이 호출하면

```javascript
sum(1, 2, 3, 4);
```

`numbers`는 다음 배열이 된다.

```javascript
[1, 2, 3, 4]
```

즉,

```text
1
2  ──── ...numbers ────► [1, 2, 3, 4]
3
4
```

와 같이 여러 값을 하나로 모은다.

### Spread Syntax

반대로 배열이나 객체를 펼칠 때에도 `...`을 사용한다.

```javascript
const numbers = [1, 2, 3];

console.log(...numbers);
```

개념적으로 다음과 같다.

```javascript
console.log(1, 2, 3);
```

따라서 다음과 같이 구분할 수 있다.

```text
Rest
여러 값을 하나로 모음

1, 2, 3
   │
   ▼
...numbers
   │
   ▼
[1, 2, 3]


Spread
하나의 구조를 여러 값으로 펼침

[1, 2, 3]
   │
   ▼
...numbers
   │
   ▼
1, 2, 3
```

# 9. Method Chaining

## 질문

다음과 같은 코드 작성 방식은 무엇인가?

```javascript
const languages = projects
    .map((project) => project.language)
    .filter((language) => language !== null)
    .filter(
        (language, index, array) =>
            array.indexOf(language) === index
    )
    .sort();
```

## 답변

하나의 객체 또는 결과에 여러 Method를 연속적으로 호출하는 **Method Chaining** 방식이다.

위 코드는 다음 순서로 처리된다.

```text
projects
    │
    ▼
map()
Project에서 Language 추출
    │
    ▼
filter()
null 제거
    │
    ▼
filter()
중복 제거
    │
    ▼
sort()
정렬
    │
    ▼
languages
```

다음 데이터를 예로 들 수 있다.

```javascript
[
    { language: "Python" },
    { language: "JavaScript" },
    { language: null },
    { language: "Python" }
]
```

### `map()`

```javascript
.map((project) => project.language)
```

결과:

```javascript
["Python", "JavaScript", null, "Python"]
```

### 첫 번째 `filter()`

```javascript
.filter((language) => language !== null)
```

결과:

```javascript
["Python", "JavaScript", "Python"]
```

### 두 번째 `filter()`

중복을 제거한다.

결과:

```javascript
["Python", "JavaScript"]
```

### `sort()`

최종 배열을 정렬한다.

이와 같은 데이터 처리 방식은 **Functional Programming의 영향을 받은 스타일**과 관련이 있다.

# 10. 정규표현식과 `test()`

## 질문

다음 코드에서 `test()` Method는 무엇을 수행하는가?

```javascript
return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
```

## 답변

`test()`는 문자열이 특정 **Regular Expression(정규표현식)** 패턴과 일치하는지 검사한다.

기본적인 형태는 다음과 같다.

```javascript
/pattern/.test("문자열");
```

반환값은 Boolean이다.

```text
패턴과 일치
└── true

패턴과 불일치
└── false
```

따라서

```javascript
/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
```

은 `email` 문자열이 지정된 이메일 형식의 패턴을 만족하는지 검사한다.

개념적으로 다음과 같다.

```text
"abc@example.com"
        │
        ▼
Regular Expression
        │
        ▼
      true


"abc"
        │
        ▼
Regular Expression
        │
        ▼
      false
```

# 11. 화살표 함수와 익명 함수

## 질문

화살표 함수와 익명 함수의 차이는 무엇인가?

## 답변

익명 함수(Anonymous Function)는 **이름이 없는 함수**를 의미한다.

```javascript
function (value) {
    return value * 2;
}
```

화살표 함수(Arrow Function)는 ES6에서 도입된 함수 표현 문법이다.

```javascript
(value) => {
    return value * 2;
}
```

한 줄의 값을 반환하는 경우 다음과 같이 축약할 수 있다.

```javascript
value => value * 2
```

따라서 다음 코드는

```javascript
numbers.map(function (number) {
    return number * 2;
});
```

다음과 같이 표현할 수 있다.

```javascript
numbers.map((number) => number * 2);
```

화살표 함수는 Callback을 간결하게 표현할 때 많이 사용된다.

다만 화살표 함수와 일반 함수는 `this` 처리 등의 동작에 차이가 있으므로 완전히 동일한 함수 문법은 아니다.

또한 **화살표 함수와 익명 함수도 동일한 개념은 아니다.**

```text
익명 함수
└── 함수에 이름이 있는지에 대한 개념

화살표 함수
└── 함수를 어떠한 문법으로 작성하는지에 대한 개념
```

# 12. HTML, CSS, JavaScript의 역할

## 질문

HTML과 CSS가 문서의 구조, 의미, 스타일을 담당한다면 JavaScript는 무엇을 담당하는가?

## 답변

JavaScript는 주로 **동작(Behavior)과 Logic**을 담당한다.

```text
HTML
"What is it?"
│
└── Structure / Semantics
    무엇이 존재하는가?


CSS
"How should it look?"
│
└── Presentation
    어떻게 표현하는가?


JavaScript
"What should it do?"
│
└── Behavior / Logic
    어떻게 동작하는가?
```

Frontend JavaScript에서는 대표적으로 다음 기능을 담당한다.

```text
JavaScript
│
├── DOM 요소 선택
├── DOM 생성 및 삭제
├── Content 변경
├── Class 변경
├── 사용자 입력 처리
├── Event 처리
├── Application State 관리
├── 데이터 처리
├── 비동기 처리
└── Server/API 통신
```

단, `document`, `fetch()`, `addEventListener()` 등의 기능은 JavaScript 언어 자체의 문법이 아니라 **Browser가 JavaScript에 제공하는 Web API**에 해당한다.

# 13. Event는 누가 발생시키는가?

## 질문

Event는 누가 발생시키며 JavaScript는 어떠한 과정으로 Event를 전달받아 처리하는가?

## 답변

사용자의 입력을 실제로 감지하고 Event를 생성하는 주체는 JavaScript 자체가 아니라 Browser와 그 하위 시스템이다.

사용자가 Mouse Button을 클릭하는 경우를 단순화하면 다음과 같다.

```text
사용자
 │
 │ Mouse Click
 ▼
Hardware / Operating System
 │
 ▼
Browser
 │
 │ Click Event 생성
 ▼
Browser Event System
 │
 ▼
등록된 JavaScript Event Handler
 │
 ▼
JavaScript 실행
```

예를 들어 다음과 같은 HTML이 존재한다고 가정한다.

```html
<button id="menu-button">
    Menu
</button>
```

JavaScript에서는 다음과 같이 Event Listener를 등록할 수 있다.

```javascript
const button = document.querySelector("#menu-button");

button.addEventListener("click", () => {
    console.log("clicked");
});
```

JavaScript가 지속적으로 Mouse 상태를 반복 검사하는 방식이 아니다.

```text
클릭 여부 확인
클릭 여부 확인
클릭 여부 확인
클릭 여부 확인
...
```

대신 Browser가 Event를 감지하고, 등록된 Listener에 해당하는 JavaScript Callback이 실행될 수 있도록 처리한다.

보다 구체적인 동작은 **Call Stack, Web API, Task Queue, Microtask Queue, Event Loop**와 연결된다.

# 14. Event → State 변경 → DOM Update

## 질문

Frontend에서 다음과 같은 흐름이 존재한다고 할 때 JavaScript가 모든 과정을 담당하는가?

```text
Event
  ↓
State 변경
  ↓
DOM Update
```

## 답변

JavaScript가 중요한 부분을 담당하지만 전체 과정이 JavaScript만으로 수행되는 것은 아니다.

메뉴 버튼을 클릭하여 Navigation의 상태를 변경하는 경우를 예로 들 수 있다.

```javascript
menuButton.addEventListener("click", () => {
    navigation.classList.toggle("active");
});
```

전체 과정은 다음과 같다.

```text
사용자 Click
    │
    ▼
Browser가 Event 감지
    │
    ▼
JavaScript Event Handler 실행
    │
    ▼
State 또는 DOM 변경
    │
    ▼
DOM/CSS 상태 변경
    │
    ▼
Browser Rendering
    │
    ▼
화면 변경
```

JavaScript는 Event Handler를 실행하고 State를 처리하며 DOM을 변경할 수 있다.

그 이후 변경된 DOM과 CSS를 바탕으로 실제 화면을 다시 그리는 것은 Browser Rendering Engine의 역할이다.

따라서 다음과 같이 역할을 구분할 수 있다.

```text
Browser
└── Event 감지

JavaScript
├── Event Handler 실행
├── State 처리
└── DOM/CSS 관련 상태 변경

Browser
├── Style 계산
├── 필요한 Layout 수행
├── Paint
└── 화면 갱신
```

# 15. `onclick`과 `addEventListener()`

## 질문

`onclick`과 `addEventListener()`의 차이는 무엇인가?

## 답변

두 방법 모두 Event Handler를 등록할 수 있다.

### `onclick`

```javascript
button.onclick = () => {
    console.log("click");
};
```

Element의 `onclick` Property에 Handler를 할당한다.

다시 할당하면 기존 Handler가 대체된다.

```javascript
button.onclick = handlerA;
button.onclick = handlerB;
```

최종적으로 `handlerB`가 할당된다.

### `addEventListener()`

```javascript
button.addEventListener("click", handlerA);
button.addEventListener("click", handlerB);
```

동일한 Event에 여러 Listener를 등록할 수 있다.

따라서 복잡한 Frontend Application에서는 일반적으로 `addEventListener()`를 사용하여 Event Listener를 관리하는 방식이 널리 사용된다.

# 16. 구조 분해 할당

## 질문

구조 분해 할당이란 무엇인가?

## 답변

**Destructuring Assignment**는 배열이나 객체에서 필요한 값을 간결하게 추출하는 문법이다.

다음 객체를 예로 들 수 있다.

```javascript
const project = {
    name: "FDANet",
    language: "Python"
};
```

기존 방식은 다음과 같다.

```javascript
const name = project.name;
const language = project.language;
```

구조 분해 할당을 사용하면 다음과 같이 작성할 수 있다.

```javascript
const { name, language } = project;
```

배열에서도 사용할 수 있다.

```javascript
const values = [10, 20];

const [first, second] = values;
```

결과는 다음과 같다.

```text
first  = 10
second = 20
```

# 17. 배열 Method

## 질문

배열 Method는 왜 필요하며 언제 사용하는가?

## 답변

Frontend에서는 JSON, API Response, 사용자 데이터 등을 배열 형태로 처리하는 경우가 많다.

예를 들어 다음과 같은 Project 데이터가 존재할 수 있다.

```javascript
const projects = [
    { name: "FDANet", language: "Python" },
    { name: "Portfolio", language: "JavaScript" },
    { name: "DGCD-Net", language: "Python" }
];
```

JavaScript는 이러한 Collection을 처리하기 위한 다양한 Array Method를 제공한다.

| Method | 목적 |
|---|---|
| `forEach()` | 각 요소에 작업 수행 |
| `map()` | 각 요소를 변환하여 새로운 배열 생성 |
| `filter()` | 조건을 만족하는 요소만 선택 |
| `find()` | 조건을 만족하는 하나의 요소 검색 |
| `some()` | 하나 이상의 요소가 조건을 만족하는지 검사 |
| `every()` | 모든 요소가 조건을 만족하는지 검사 |
| `sort()` | 요소 정렬 |
| `reduce()` | 여러 값을 하나의 결과로 누적 |

예를 들어 Python으로 작성된 Project의 이름만 추출하려면 다음과 같이 작성할 수 있다.

```javascript
projects
    .filter((project) => project.language === "Python")
    .map((project) => project.name);
```

결과는 다음과 같다.

```javascript
["FDANet", "DGCD-Net"]
```

따라서 Array Method는 **Collection 데이터를 검색, 변환, 필터링, 정렬, 집계하기 위한 기본 도구**라고 할 수 있다.

# 18. `event.preventDefault()`

## 질문

`event.preventDefault()`는 무엇인가?

## 답변

Browser에는 특정 Event가 발생했을 때 자동으로 수행하는 **Default Action**이 존재한다.

예를 들어 Form Submit Event가 발생하면 Browser는 기본적으로 Form을 제출하는 동작을 수행할 수 있다.

```javascript
form.addEventListener("submit", (event) => {
    event.preventDefault();

    ...
});
```

`preventDefault()`는 해당 Event에 연결된 **Browser의 기본 동작을 취소**한다.

이를 이용하면 JavaScript에서 직접 다음과 같은 처리를 수행할 수 있다.

```text
Submit Event
     │
     ▼
preventDefault()
     │
     ├── Browser 기본 Submit 동작 취소
     │
     ▼
JavaScript
     │
     ├── Validation
     ├── 데이터 처리
     └── API Request
```

`preventDefault()`가 Event 자체를 제거하는 것은 아니다.

Event는 이미 발생하였으며 Event Handler도 실행되고 있다.

취소되는 것은 **해당 Event에 대응하는 Browser의 기본 동작**이다.

# 20. 웹 퍼블리셔와 Frontend Developer

```text
Design
   │
   ▼
HTML
CSS
기본적인 JavaScript
   │
   ▼
Web Page
```

- HTML
- CSS
- Semantic Markup
- Responsive Design
- Accessibility
- Cross-browser 대응
- Animation
- 디자인의 웹 화면 구현

Frontend Developer는 UI 구현뿐만 아니라 **Client Application의 동작과 데이터 처리**까지 담당하는 경우가 일반적이다.

```text
├── Testing
```

이를 단순화하면 다음과 같이 구분할 수 있다.

```text
└── 디자인과 문서 구조를
    웹 화면으로 구현
        │
        └── HTML / CSS 중심
            + 필요한 JavaScript

│
└── 웹 화면을 포함한
    Client Application 구현
        │
        ├── HTML / CSS
        ├── JavaScript / TypeScript
        ├── State
        ├── Event
        ├── API
        ├── Application Logic
        └── Architecture
```
